## 一、产品概述

### 1.1 产品定位

**医研千问**是一款基于 **TotrialDriver 大模型**的临床研究领域**智能问答助手**，旨在为临床试验研究人员提供专业、准确的临床研究知识问答，涵盖试验设计指导、法规解读、专业术语解释、研究流程咨询等场景，帮助研究人员快速获取专业建议，提升工作效率。

### 1.2 目标用户

| 用户角色 | 典型场景 | 核心诉求 |
|----------|----------|----------|
| 临床研究人员 | 查询试验设计规范、统计方法 | 快速获取专业、准确的答案 |
| CRA/CRC | 咨询GCP规范、操作流程 | 确保操作合规，减少差错 |
| 药企临床开发人员 | 了解CDE指导原则、监管要求 | 及时掌握最新法规动态 |
| 医院研究者/PI | 专业术语解释、文献检索 | 快速理解专业内容 |

### 1.3 产品愿景

成为临床研究领域首选的 AI 问答工具，以 TotrialDriver 大模型的专业能力为基础，帮助研究人员快速解决临床研究中的知识性问题。

## 二、业务背景

### 2.1 行业痛点

1. **专业知识获取困难** — 临床研究涉及大量法规、指导原则、专业术语，研究人员需频繁查阅文档
2. **法规更新频繁** — CDE/ICH 等指导原则持续更新，研究人员难以及时掌握最新动态
3. **跨部门沟通成本高** — 不同角色对同一专业问题理解不一致，需反复确认
4. **经验沉淀不足** — 资深研究者的经验难以结构化沉淀，新人学习曲线陡峭
5. **AI 工具缺乏项目上下文** — 现有 AI 工具（如通用大模型）回答时无法基于具体项目的专属资料（试验方案、SOP、行业指南），容易给出泛化或不准确的回复，产生"AI 幻觉"

### 2.2 解决方案

通过基于 TotrialDriver 大模型的"医研千问"智能问答助手，实现：

- **专业领域问答** — 覆盖临床试验设计、GCP规范、CDE指导原则、ICH规范等核心知识
- **法规动态解读** — 及时解读最新监管要求，帮助研究人员合规操作
- **术语解释** — 提供准确的临床研究专业术语释义
- **多轮对话** — 支持上下文关联的连续提问，深入探讨专业问题
- **项目知识沙盒** — 以"临床项目"为容器构建专属知识库，实现数据隔离，消除 AI 幻觉，并实现 AI 生成产物的知识反哺

### 2.3 竞品分析

| 维度 | 医研千问 | 通用大模型 | 专业数据库检索 |
|------|----------|------------|----------------|
| 专业深度 | TotrialDriver临床领域大模型 | 通用知识，临床深度不足 | 结构化检索，缺乏解读 |
| 交互方式 | 自然语言多轮对话 | 自然语言对话 | 关键词检索 |
| 法规时效 | 定期更新知识库 | 训练数据截止 | 更新及时 |
| 使用门槛 | 低（对话式） | 低（对话式） | 高（需专业知识） |

### 3.2 功能详细说明

#### 3.2.1 智能问答模块

**功能描述**：用户输入临床研究相关问题，系统基于 TotrialDriver 大模型提供专业、准确的回答。

**支持的问答领域**：

| 领域 | 示例问题 |
|------|----------|
| 试验设计 | "II期临床试验的样本量一般如何确定？" |
| GCP规范 | "什么是SAE？报告时限是多久？" |
| CDE指导原则 | "抗肿瘤药物II期临床研究的终点如何选择？" |
| 统计方法 | "非劣效性试验的界值如何确定？" |
| 专业术语 | "FAS集和PPS集的区别是什么？" |
| 注册法规 | "IND申报需要提交哪些临床相关资料？" |
| 伦理审查 | "伦理委员会审查的重点是什么？" |

**交互流程**：
```
用户提问 → 问题理解 → TotrialDriver推理 → 生成回答 → 展示结果（含引用来源）
       ↓
   追问/新话题 → 上下文记忆 → 连续对话
```

**核心能力**：
1. **多轮对话** — 支持上下文关联的连续提问，自动理解指代和省略
2. **引用溯源** — 回答中关键结论附带法规/指南出处
3. **专业术语解释** — 自动识别术语并提供简明释义
4. **追问引导** — 回答末尾推荐相关追问方向

**API接口**：

```
POST /api/chat/send
Request Body:
{
  "message": string,           // 用户输入
  "conversationId": string,    // 会话ID（可选，用于多轮对话）
  "domain": string             // 领域标签（可选，如"GCP", "统计", "法规"）
}

Response:
{
  "answer": string,            // AI回答
  "citations": [               // 引用来源
    {
      "source": string,        // 法规/指南名称
      "section": string,       // 具体章节
      "url": string            // 原文链接（如有）
    }
  ],
  "suggestedQuestions": [      // 推荐追问
    string
  ],
  "conversationId": string     // 会话ID
}
```

#### 3.2.2 项目知识库（知识沙盒）

**功能描述**：以"临床项目"为容器构建专属知识沙盒，实现项目级数据隔离，确保 AI 回答基于项目专属资料，消除 AI 幻觉，同时实现 AI 生成产物的知识反哺。

**背景**：现有的 AI 工具（如医研千问、AI Screening）在处理特定临床项目时，需要基于该项目的专属资料（如试验方案、SOP、行业指南）才能给出严谨的回复。项目知识库的引入正是为了解决这一问题。

**核心概念**：

| 概念 | 说明 |
|------|------|
| 项目容器 | 以临床项目为单位的知识隔离空间，每个项目拥有独立的知识库 |
| 知识沙盒 | 项目间的知识完全隔离，AI 回答时仅检索当前项目的知识库，避免跨项目混淆 |
| 知识反哺 | AI 生成的优质回答、方案建议等可归档为项目知识，反哺知识库持续完善 |

**功能模块**：

**a) 项目容器管理**

| 功能 | 说明 |
|------|------|
| 创建项目 | 输入项目名称或项目号 |
| 编辑项目 | 修改项目名称或项目号|
| 删除项目 | 软删除，保留数据可恢复 |
| 成员管理 | 项目管理员/成员/只读三种角色，控制上传、删除权限 |
| 资料分类 | 试验方案、SOP、行业指南、CDE指导原则、内部规范等 |

**b) 知识文档管理**

| 功能 | 说明 |
|------|------|
| 文档上传 | 支持 PDF、Word(.docx)、TXT、Markdown 格式 |
| 批量上传 | 支持一次上传多个文件 |
| 文档解析 | 自动提取文档结构（标题、段落、表格）并向量化 |
| 文档版本 | 同一文档多次上传时保留历史版本 |
| 文档检索 | 关键词搜索 + 语义检索，快速定位相关文档 |
| 文档预览 | 在线预览上传的文档内容 |
| 文档删除 | 从知识库中移除文档，同时删除向量索引 |

**c) 知识沙盒隔离**

| 机制 | 说明 |
|------|------|
| 项目级数据隔离 | 项目A的知识库无法被项目B的对话检索到 |
| 专属知识问答上下文 | 切换到项目模式后，AI 回答优先基于项目知识库，辅以通用知识库 |
| 跨项目知识隔离 | 不同项目之间的文档、对话历史完全隔离 |

**d) 知识反哺**

| 功能 | 说明 |
|------|------|
| AI生成产物归档 | 对话中生成的方案建议、总结等内容可一键归档为项目知识文档 |
| 优质问答对沉淀 | 标记高质量的问答对，加入项目 FAQ |
| 知识库更新建议 | AI 自动识别回答中的知识盲区，建议补充相关文档 |

**交互流程**：

```
用户进入项目 → 选择/创建项目 → 上传项目资料 → 系统解析并向量化 → 切换到项目问答模式
                                                                    ↓
用户提问 → 检索项目知识库 → TotrialDriver基于项目知识推理 → 生成回答（标注项目知识来源）
                                                                    ↓
优质问答 → 标记沉淀 → 补充项目FAQ
AI产物 → 一键归档 → 新增项目知识文档
```

**API接口**：

```
// 创建项目
POST /api/projects
Request Body:
{
  "name": string,             // 项目名称
  "code": string,             // 项目编号
  "indication": string,       // 适应症
  "phase": string,            // 试验分期
  "description": string       // 项目描述
}

// 上传项目文档
POST /api/projects/:id/documents
Request Body: multipart/form-data
{
  "files": File[],            // 文档文件
  "category": string          // 文档分类
}

// 项目知识问答
POST /api/projects/:id/chat
Request Body:
{
  "message": string,          // 用户输入
  "conversationId": string    // 会话ID（可选）
}

Response:
{
  "answer": string,
  "citations": [
    {
      "documentName": string, // 项目文档名称
      "section": string,      // 章节/页码
      "content": string       // 引用片段
    }
  ],
  "conversationId": string
}
```

#### 3.2.3 通用知识库管理

**功能描述**：管理医研千问背后的通用专业知识库，确保回答的准确性和时效性。

**知识库分类**：

| 类别 | 内容 | 更新频率 |
|------|------|----------|
| 法规库 | 药品管理法、GCP、伦理审查办法等 | 法规发布后一周内 |
| 指导原则库 | CDE/ICH指导原则、技术指南 | 发布后一周内 |
| 统计规范 | ICH-E9、样本量计算指南等 | 更新时同步 |
| 术语库 | 临床研专业术语及释义 | 定期维护 |

**知识库更新机制**：
- 自动抓取：对接CDE/ICH官网，监控新规发布
- 人工审核：专业编辑团队审核后入库
- 版本管理：保留历史版本，支持追溯

#### 3.2.4 对话历史管理

**功能描述**：管理用户的历史对话记录，支持回顾、收藏、导出。

**核心功能**：
- **历史列表**：按时间倒序展示所有对话会话
- **搜索**：按关键词搜索历史对话内容
- **收藏**：标记重要对话方便后续查找
- **导出**：支持导出为 Markdown/PDF 格式
- **删除**：用户可自主删除历史对话记录

### 3.3 非功能性需求

#### 3.3.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 问答响应时间 | ≤ 5秒 | 单次对话API响应时间 |
| 多轮对话上下文 | ≤ 1秒 | 上下文加载时间 |
| 并发支持 | 50路/实例 | 单台服务器同时对话数 |

#### 3.3.2 可用性要求

- 服务可用性：99.5%（月度）
- 对话历史持久化：用户对话永久保存，除非主动删除

#### 3.3.3 安全要求

- 数据隔离：用户只能查看自己的对话历史
- 传输加密（HTTPS）
- 内容安全：回答经合规过滤器审核

### 4.2 交互规则

#### 4.2.1 对话规则

1. 用户可在**通用问答**和**项目问答**之间切换
2. 通用问答模式下，AI 基于通用知识库回答
3. 项目问答模式下，AI 优先基于项目知识库回答，辅以通用知识库
4. 支持多轮连续对话，系统自动维护上下文
5. 回答中关键结论附带引用来源（📖图标），标注来源文档名称和章节
6. 回答末尾推荐2-3个相关追问方向
7. 支持一键开启新话题（清空上下文）

#### 4.2.2 项目知识库规则

1. 创建项目时需填写项目名称和编号，其他信息可选
2. 上传文档后系统自动解析并向量化，状态显示"处理中"→"已完成"
3. 同一文档多次上传时自动版本管理，保留历史版本
4. 项目成员权限：管理员（全部操作）、成员（上传/问答）、只读（仅问答）
5. 支持一键将优质问答对归档为项目 FAQ
6. AI 生成产物可一键保存为项目知识文档

#### 4.2.3 错误处理

| 场景 | 处理方式 |
|------|----------|
| 模型服务超时 | 显示"思考中，请稍后..."，自动重试1次 |
| 无法回答 | 诚实告知超出知识范围，建议查阅官方文档 |
| 项目知识库为空 | 提示"当前项目暂无资料，请先上传文档" |
| 文档解析失败 | 提示具体错误原因（格式不支持/文件损坏等） |
| 网络中断 | 显示"网络异常，正在重连..." |
| 敏感内容 | 拦截并提示"该问题暂无法回答" |

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| TotrialDriver服务不稳定 | 问答失败/响应慢 | 降级提示+自动重试；多模型冗余备份 |
| 回答准确性不足 | 误导用户 | 引用溯源必带；关键结论人工审核提示 |
| 知识库更新滞后 | 回答过期内容 | 建立法规监控+定期审核机制 |
| 敏感内容泄露 | 合规风险 | 内容过滤；访问日志审计 |
| 项目知识隔离失效 | 跨项目数据泄露 | 向量数据库集合级隔离；接口权限校验 |
| 文档解析失败率高 | 项目知识无法使用 | 多引擎备选；明确错误提示；支持手动录入 |

## 八、验收标准

### 8.1 功能验收

- [ ] 用户提问后，5秒内返回专业回答
- [ ] 回答中关键结论附带引用来源（法规/指南名称+章节）
- [ ] 支持5轮以上连续对话，上下文理解准确
- [ ] 专业术语回答准确，释义与官方定义一致
- [ ] 推荐追问与当前话题相关性强
- [ ] 项目模式下，回答优先基于项目知识库，引用项目文档
- [ ] 项目间知识完全隔离，无跨项目泄露

### 8.2 性能验收

- [ ] API响应时间 < 5秒（单次对话）
- [ ] 多轮对话上下文加载 < 1秒
- [ ] 支持50路并发对话
- [ ] 文档解析时间 < 30秒/10页

### 8.3 质量验收

- [ ] 回答准确率经临床专家抽样审核 > 90%
- [ ] 引用溯源准确率 > 95%
- [ ] 无编造法规/指南条目的情况
- [ ] 项目模式下，基于项目文档的回答准确率 > 95%
