# 观严代扣代缴 —— 后台开关深度分析

> 基于《观严平台代扣代缴设计方案V2.5》PART 01（Slide 3-4），拆解业务逻辑、开关机制、状态流转、页面需求与边界情况，为后续原型生成提供结构化输入。

---

## 一、核心业务概念

### 1.1 两种代扣模式

| 维度 | 观严代办申报（开关=开） | 云账户代办（开关=关） |
|------|------------------------|----------------------|
| 谁扣税 | 观严系统算税并代扣个税+增附税 | 云账户依法代扣代缴 |
| 谁打款 | 观严平台打款 | 云账户打款 |
| 是否需签知情同意书 | **必须签署**《个人所得税、增值税等代办申报知情同意书》 | 不需要 |
| 个税计算方式 | 用户自选：累计预扣法 / 按次预扣法 | 云账户自有逻辑 |
| 增值税处理 | 观严代扣（逐笔冻结 / 客户兜底二选一） | 云账户处理 |
| 当前状态 | 新模式，正在过渡 | **现有模式** |

**一句话**：开关的本质是决定每个劳动者走哪条代扣链路——观严还是云账户。

### 1.2 为什么需要两层开关

这是一个**过渡期设计**：

```
过渡期                              过渡完成后
┌───────────────────────┐          ┌───────────────────────┐
│ 总闸 = 开             │          │ 总闸 = 关             │
│                       │          │                       │
│  人员A → 观严代办 ✓   │  逐步    │  人员A → 观严代办 ✓   │
│  人员B → 云账户   ✓   │ ──────→ │  人员B → 观严代办 ✓   │
│  人员C → 观严代办 ✓   │  迁移    │  人员C → 观严代办 ✓   │
│  (可按人配置)          │          │  (全员统一，人员级失效) │
└───────────────────────┘          └───────────────────────┘
```

- **过渡期**：部分人在观严、部分人在云账户，需要按人差异化配置
- **过渡完成**：所有人统一走观严，不再需要人员级配置

## 二、两层开关机制详解

### 2.1 第一层：总闸——人员差异化代扣配置

| 状态 | 含义 | 影响范围 |
|------|------|---------|
| **开启**（默认，过渡期） | 允许按人员配置代扣模式 | 人员级开关生效，可逐人设为观严或云账户 |
| **关闭**（过渡完成） | 全平台统一走观严代扣 | 人员级开关**失效**，所有人强制走观严代办 |

关键规则：
- 总闸默认开启（当前处于过渡期）
- 关闭总闸 = 宣布过渡完成，是**不可逆操作**（或至少需要极高确认门槛）
- 关闭后，所有人员级开关变为只读/灰色，显示"已统一走观严代办"

### 2.2 第二层：人员开关——观严代办申报

| 状态 | 含义 | 下游影响 |
|------|------|---------|
| **开启** | 该人员走观严代办申报 | 需签知情同意书 → 观严算税扣税 → 观严打款 |
| **未开启** | 该人员走云账户代办 | 无需签知情同意书 → 云账户扣税打款 |

关键规则：
- 人员开关仅在总闸=开启时有效
- 人员开关=开启时，用户侧必须签署知情同意书（未签署则无法费用申请/收款/提现）
- 人员开关=未开启时，用户侧无观严代办入口

### 2.3 开关组合矩阵

| 总闸 | 人员开关 | 实际代扣模式 | 用户侧影响 |
|------|---------|-------------|-----------|
| 开启 | 开启 | 观严代办 | 需签知情同意书，前台显示"代办申报"入口 |
| 开启 | 未开启 | 云账户代办 | 不签，前台无代办申报入口 |
| 关闭 | （失效）| 观严代办（全员） | 全员需签，前台统一显示"代办申报"入口 |
| 关闭 | （失效）| 观严代办（全员） | 同上 |

## 三、开关与下游功能的联动关系

后台开关是整个代扣代缴体系的**源头控制点**，直接决定后续所有流程走向：

```
后台开关配置
    │
    ├─ 人员开关=开 ──→ 前台展示"代办申报"入口
    │                    │
    │                    ├─ 未实名 → 先实名 → 引导签署
    │                    ├─ 已实名未签署 → 引导签署
    │                    └─ 已签署 → 正常费用申请/收款/提现
    │
    ├─ 人员开关=关 ──→ 前台无"代办申报"入口
    │                    └─ 走云账户流程
    │
    └─ 总闸=关 ──→ 全员同"人员开关=开"
```

### 3.1 开关变更对已签署用户的影响

| 变更场景 | 影响 | 处理方式 |
|---------|------|---------|
| 人员开关从"开"→"关" | 用户已签的知情同意书如何处理？ | 需确认：协议是否保留/作废？已扣税记录是否保留？ |
| 人员开关从"关"→"开" | 用户需新签知情同意书 | 走新签流程 |
| 总闸从"开"→"关" | 原云账户人员需补签 | 批量引导签署，或冻结余额倒逼签署 |

**待确认问题**：
1. 人员开关能否随意切换？还是一旦开启就不可关闭？
2. 开关从开→关时，已签署用户已有余额的代扣逻辑？
3. 总闸关闭时，未签署的云账户用户如何批量迁移？

## 四、后台开关相关页面需求

### 4.1 页面清单

| 序号 | 页面名称 | 页面目标 | 核心操作 |
|------|---------|---------|---------|
| P1 | 代扣模式总配置页 | 管理总闸和查看全局状态 | 开关总闸、查看统计、跳转人员配置 |
| P2 | 人员代扣配置列表页 | 按人员管理代扣模式 | 搜索/筛选、单个开关、批量操作 |
| P3 | 人员代扣详情侧滑/弹窗 | 查看单人完整状态 | 查看实名/签署/代扣方式/余额状态 |
| P4 | 总闸关闭确认弹窗 | 防止误操作 | 二次确认、展示影响范围 |
| P5 | 批量设置代扣模式弹窗 | 批量修改人员开关 | 选择人员、设为观严/云账户 |

### 4.2 P1：代扣模式总配置页

**页面目标**：让管理员在一个页面了解全局代扣配置状态，并控制总闸。

**核心内容**：
- 总闸开关（人员差异化代扣配置）
  - 当前状态：开启 / 关闭
  - 状态说明文案
- 统计卡片
  - 观严代办人数 / 总人数
  - 已签署知情同意书人数 / 观严代办人数
  - 云账户代办人数
  - 未实名人数（仅观严代办人员）
- 操作入口
  - 「管理人员配置」→ 跳转 P2
- 过渡期提示
  - 总闸=开时：「当前处于过渡期，可按人员差异化配置代扣模式」
  - 总闸=关时：「过渡已完成，全平台统一走观严代办申报」

**状态与交互**：
- 切换总闸时弹出 P4 确认弹窗
- 总闸=关时，统计卡片中"云账户代办人数"应为 0

### 4.3 P2：人员代扣配置列表页

**页面目标**：按人员维度管理代扣模式，支持搜索、筛选、单个和批量操作。

**核心内容**：
- 筛选条件
  - 代扣模式：全部 / 观严代办 / 云账户代办
  - 签署状态：全部 / 已签署 / 未签署 / 需重签（仅观严代办人员）
  - 实名状态：全部 / 已实名 / 未实名（仅观严代办人员）
  - 关键词搜索（姓名/手机号/证件号）
- 列表字段
  - 姓名
  - 手机号
  - 证件号码（脱敏）
  - 代扣模式标签（观严代办 / 云账户代办）
  - 实名状态（已实名 / 未实名）
  - 签署状态（已签署 / 未签署 / 需重签 / —）
  - 个税计算方式（累计预扣法 / 按次预扣法 / —）
  - 操作：切换开关 / 查看详情
- 批量操作
  - 勾选多人 → 批量设为观严代办 / 批量设为云账户代办
- 分页

**状态与交互**：
- 总闸=关时，代扣模式列全部显示"观严代办"，操作列不显示切换按钮
- 切换人员开关时，需确认提示（告知影响）
- **从"观严"→"云账户"时**：
  - 若已签署+有余额 → **禁止切换**，提示"该用户有余额，无法切换为云账户模式，余额为0后方可切换"
  - 若已签署+无余额 → 允许切换，提示"切换后观严代扣将关闭"
- 从"云账户"→"观严"时：需提示"该用户需签署知情同意书后才能正常使用"

### 4.4 P3：人员代扣详情侧滑/弹窗

**页面目标**：查看单个人员的完整代扣相关状态。

**核心内容**：
- 基本信息：姓名、手机号、证件号码
- 实名状态：已实名 / 未实名（实名时间）
- 代扣模式：观严代办 / 云账户代办
- 签署状态：已签署 / 未签署 / 需重签
  - 已签署时：签署时间、选择方式（累计/按次）、协议版本
  - 未签署时：无更多信息
- 余额信息：可用余额、冻结金额
- 授权历史（如有关联记录）

### 4.5 P4：总闸关闭确认弹窗

**页面目标**：防止误操作，清晰展示关闭总闸的影响。

**核心内容**：
- 操作说明：「关闭人员差异化代扣配置」
- 影响提示：
  - 「关闭后，全平台所有人员将统一走观严代办申报」
  - 「当前有 X 人走云账户代办，关闭后这些人将需要签署知情同意书」
  - 「人员级代扣配置将不再生效」
  - 「此操作将影响全平台代扣模式，请谨慎确认」
- 确认操作：输入"确认关闭"文字 → 点击确认
- **已确认：总闸可逆，但需谨慎操作**（确认弹窗保留，不标注"不可逆"）

### 4.6 P5：批量设置代扣模式弹窗

**页面目标**：批量修改选中人员的代扣模式。

**核心内容**：
- 已选择 N 人
- 操作选择：设为观严代办 / 设为云账户代办
- 影响提示：
  - 设为观严代办时：「这些人员将需要签署知情同意书」
  - 设为云账户代办时：「这些人员的观严代扣将被关闭，已签署的协议将…」
- 确认按钮
- **已确认规则：已签署+有余额的用户不可切回云账户；余额为0后可切换**

## 五、关键状态机

### 5.1 人员代扣状态流转

```
                    ┌──────────────────────┐
                    │     云账户代办        │
                    │ （开关=关，无需签署）  │
                    └──────────┬───────────┘
                               │ 开关→开
                               ▼
                    ┌──────────────────────┐
                    │   观严代办-未签署     │
                    │ （开关=开，需签署）    │
                    │  → 无法费用申请/收款   │
                    └──────────┬───────────┘
                               │ 签署知情同意书
                               ▼
                    ┌──────────────────────┐
                    │   观严代办-已签署     │
                    │ （选择累计/按次）      │
                    │  → 正常使用           │
                    └──────────┬───────────┘
                               │ 协议更新
                               ▼
                    ┌──────────────────────┐
                    │   观严代办-需重签     │
                    │  → 同未签署限制       │
                    └──────────┬───────────┘
                               │ 重新签署
                               ▼
                    ┌──────────────────────┐
                    │   观严代办-已签署     │
                    └──────────────────────┘
```

### 5.2 总闸状态

```
总闸=开（过渡期，默认）  ←────→  总闸=关（过渡完成）
   │                          │        可逆，但需谨慎
   │ 人员级可配置              │
   │ 可按人走观严/云账户       │ 人员级不可配置
   │                         │ 全员走观严
```

## 六、边界情况与待确认问题

### 6.1 已识别的边界情况

| 场景 | 问题 | 已确认处理方式 |
|------|------|--------------|
| 总闸关闭时，云账户用户有余额 | 余额如何处理？ | 冻结余额，签署后释放 |
| 人员开关频繁切换 | 是否允许？ | **已签署+有余额：不可切回云账户；余额=0后可切换** |
| 批量设置中包含已签署用户 | 如何处理？ | 确认弹窗分开展示影响，有余额的自动跳过并提示 |
| 总闸关闭后想重新开启 | 是否允许？ | **已确认：可逆，但需谨慎操作（二次确认）** |
| 开关变更时用户正在费用申请中 | 如何处理？ | 按变更前逻辑完成当前申请 |
| 同一人在多个项目中 | 开关是全局还是项目级？ | 方案暗示是人员级全局，需确认 |

### 6.2 已确认决策汇总

1. **总闸是否可逆**：✅ 可逆，但需谨慎操作（确认弹窗保留）
2. **人员开关限制**：✅ 已签署+有余额 → 不可切回云账户；余额=0后可切换
3. **权限控制**：✅ 仅管理员可以配置总闸和人员开关
4. **批量操作上限**：待确认
5. **操作日志**：建议保留，待确认

## 七、页面优先级建议

| 优先级 | 页面 | 理由 |
|--------|------|------|
| P0 | P1 代扣模式总配置页 | 核心入口，必须先有 |
| P0 | P2 人员代扣配置列表页 | 日常操作最高频的页面 |
| P1 | P4 总闸关闭确认弹窗 | 风险操作的必要保护 |
| P1 | P5 批量设置弹窗 | 过渡期高频操作 |
| P2 | P3 人员详情侧滑 | 辅助查看，可后续迭代 |
