# AI Monitoring 对话式核查迭代 PRD（草稿）

## 1. 背景与目标

### 1.1 背景
AI Monitoring 目前已具备完整的“材料上传 → 4步核查 → 报告输出”闭环，但其交互仍以“表单驱动”为主，用户需要提前理解并逐项填写参数，流程较重，缺乏交互引导和增量补充能力。随着产品进一步迭代，目标是将 AI Monitoring 从“任务型工具”升级为“对话式核查助手”。

### 1.2 目标
1. 让用户无需提前理解所有配置项，AI 可以通过对话逐步引导补充材料与参数。
2. 在核查完成后保留底部对话框，允许用户继续上传补充材料、补充说明、追问问题，并重新生成问题清单和报告。
3. 保留现有结构化核查流程与结果展示的稳定性，降低用户学习成本。
4. 提升 AI Monitoring 的可用性、可跟踪性和迭代能力，支持“补充材料 → 重新核查”的闭环。

### 1.3 产品定位
AI Monitoring 作为临床研究数据核查助手，以“AI 引导式核查”帮助用户完成材料收集与检查，以“核查结果呈现”快速识别关键问题，以“对话式补充”支持后续增量修正与复核，以“增量重查”降低用户反复重新上传全量材料的成本。

---

## 2. 用户与场景

### 2.1 目标用户
- 临床研究协调员（CRC）
- 监查员（CRA）
- 数据管理人员（DM）
- 研究负责人 / 研究中心人员

### 2.2 核心场景
1. 用户首次进入 AI Monitoring，点击示例或上传材料，启动一次核查任务。
2. 用户在核查前，通过对话式引导补充方案、CRF、知情同意日期、基线日期等材料。
3. 核查完成后，用户可直接在底部对话框追问问题或补充材料。
4. 用户补充额外材料后，系统支持重新生成更新后的问题清单和报告。
5. 用户可以查看历史版本与当前版本的差异，便于追踪核查演进。

## 3. 范围

### 3.1 本次迭代范围

| 类别 | 内容 |
|------|------|
| 新增功能 | 初始页示例入口；核查完成后的底部对话框；对话式补充材料与重新核查；对话式调整项目设置参数并重新生成问题清单；版本历史展示 |
| 保持不变 | 现有材料准备流程（试验方案、CRF、知情同意日期、基线日期、待查数据上传）；4步核查流程；一键启动核查 |
| 不做 | 跨任务切换；项目级配置修改；非临床泛化问答；外部系统集成 |

### 3.2 对话能力边界

| 允许 | 不允许 |
|------|--------|
| 补充材料、追问问题、解释结果、重查更新 | 跨任务切换 |
| 调整当前任务的项目设置参数，设置后重新生成问题清单 | 修改项目级全局配置 |
| 回答与临床相关的泛化问题 | 非临床领域的泛化问答 |

## 4. 需求概述

### 4.1 总体原则
- 维持现有结构化核查的主流程，不做大规模重建。
- 对话能力仅作为增量增强能力，不覆盖全部业务流程。
- 对话是“补充材料、追问解释、重查更新”的补充能力，而非完全替代核查流程。
- 用户必须能在现有页面中快速理解“下一步该做什么”。

### 4.2 设计思路
采用“结构化 + 对话增强”的混合模式：

- 顶部和中部保持当前的结构化任务区域
- 底部新增对话框，支持：
  - 上传补充材料
  - 提问与解释
  - 触发重新核查
- AI 在完成核查后可提示：
  - “检测到补充材料，可重新生成问题清单和报告”
  - “当前问题已更新，建议重新核查”

## 5. 功能需求

### 5.1 初始页增加示例入口
在 AI Monitoring 的初始空状态页增加示例卡片，支持用户直接点击进入核查流程。

示例包括：
- 示例 A：冠心宁片受试者核查
- 示例 B：盐酸安罗替尼数据核查
- 示例 C：补充材料后重新核查示例（新增）

点击示例后，需要满足：
- 自动生成对应任务
- 自动填充默认材料和参数
- 自动进入核查流程
- 直接展示问题清单和报告结果

### 5.2 现有流程保持不变
在“材料准备”和“4步核查”阶段，保持现有用户体验：

- 试验方案上传
- 空白 CRF 上传
- 知情同意日期和 D0 基线日期设置
- 待查数据上传
- 一键启动核查

### 5.3 底部对话框增强
在核查完成后，页面底部新增对话区域，用户可以：
- 直接输入文本
- 直接上传补充材料
- 追问“Critical / Major / Minor 问题是什么意思”
- 询问“是否需要补充更多资料”
- 发起“重新核查”

对话框的能力边界：
- 支持补充材料、追问问题、解释结果、重查更新
- 可以调整项目设置参数，设置后，重新生成问题清单
- 不负责跨任务切换
- 若问答脱离核查场景的泛化问题，且与临床相关，AI 进行回答

对话框能力边界细化：
1. 核心能力：
   - 允许用户在结果页继续补充材料、解释现有问题、提出下一步核查建议
   - 允许用户通过对话修改与当前任务直接相关的项目设置参数，如：基线日期、方案版本、关键字段定义等
   - 修改后可立即触发“重新生成问题清单”，而不必重新走完整的初始化流程
2. 允许的动作：
   - 上传新增材料
   - 对问题级别进行解释
   - 追问已有问题的判定依据
   - 更新任务参数并生成新版本结果
3. 禁止动作：
   - 直接跳转到其他任务或项目
   - 擅自篡改已正式确认的研究配置项
   - 对非本任务内容做无关回答
4. 泛化问题处理：
   - 若用户提问为临床研究范畴的概念，例如“什么是关键偏差”“为何需要基线时间点”，可由 AI 作简短解释并引导回当前核查任务
   - 若是与当前任务无关的泛化闲聊或完全非临床内容，系统应限制回答并提示继续核查主线
5. 执行顺序：
   - 用户输入/上传 → AI 判断是否属于本任务补充、参数调整或解释场景 → 触发对应动作 → 生成更新后的问题清单或结论

### 5.4 补充材料并重新核查
当用户在结果页补充材料时，系统支持：

1. 用户上传额外文件
2. AI 识别新增材料类型和内容
3. AI 给出更新确认：
   - “已收到补充材料”
   - “建议将新材料纳入本次复核”
4. 用户确认后触发“重新核查”
5. 系统重新执行核查流程，生成新一版问题清单和报告
6. 结果页展示历史版本与当前版本差异

### 5.5 重新生成问题清单和报告
重新核查后，系统需生成：
- 更新后的问题清单
- 问题等级重排序
- 已解答 / 已修正问题状态
- 更新后的综合结论
- 版本信息，如 V1、V2、V3

## 6. 业务流程

### 6.1 典型主流程
1. 用户进入 AI Monitoring
2. 点击示例或上传材料
3. AI 引导完成必要资料收集
4. 触发智能核查
5. 4步核查完成
6. 展示问题清单和报告
7. 用户在底部继续提问或补充材料
8. 发现新增材料后，可执行“重新核查”
9. 生成更新版问题清单与报告

### 6.2 对话补充流程
1. 用户在结果页面输入：“我还有一份出院小结，补充一下”
2. 系统识别为“补充材料”
3. AI 显示：
   - “已收到补充文件”
   - “已识别：出院诊断、基线信息、治疗过程”
4. AI 提示：
   - “建议重新核查并更新问题清单”
5. 用户点击“重新核查”
6. 系统执行增量重检并输出新结果

## 7. 规则与约束

### 7.1 任务边界规则
- 当前会话仅允许处理本任务的相关材料
- 补充材料必须与当前任务相关，不能跨项目带入
- 详细边界定义见 §3.2 对话能力边界

### 7.2 重查规则
- 用户补充材料后，系统默认建议重新核查
- 重新核查应基于新材料和旧材料共同生成更新结果
- 重新核查必须保留历史版本并展示差异
- 对于“已修复”问题，需在结果中明确显示为已处理

### 7.3 对话规则
- 对话区仅保留与核查有关的能力
- 允许回答与当前任务相关的临床概念、问题解释、补充材料识别、参数调整建议和重查策略
- 对完全无关的泛化问题进行“温和拒绝 + 引导回主线”
- 对专业概念问题可给出简短解释，并提示与正在进行的核查维度关联
- 对于可能影响任务结论的参数修改，需在对话中明确说明调整项、影响范围和是否触发重查

### 7.4 版本规则
- 每次重查产生新版本
- 版本记录保留：
  - 时间
  - 材料变更摘要
  - 问题变化
  - 是否为重查版本

### 7.5 任务状态流转规则
- 任务进入"材料收集中"后，允许用户通过对话补充材料或参数
- 用户补充材料并确认纳入核查，任务状态变为"重新核查中"
- 用户仅进行解释或追问，不新增材料，任务维持"已完成"状态，仅更新结果说明
- 用户修改项目参数并确认生效，系统生成新一版问题清单，并记录"参数变更"作为版本差异项
- 未完成的任务在对话中被补充后，系统展示"下一步建议：重新核查"

## 8. 状态设计

### 8.1 任务状态
- 未开始：初始状态
- 材料收集中：等待材料补充
- 核查中：正在执行核查
- 已完成：核查结束，结果已生成
- 重新核查中：已补充材料或修改参数，正在重新核查
- 已归档：任务封存

### 8.1.1 状态流转示例
- 未开始 → 材料收集中：用户上传材料或选中示例
- 材料收集中 → 核查中：用户确认开始核查
- 核查中 → 已完成：核查完成，问题清单和报告生成
- 已完成 → 重新核查中：用户追加材料或修改参数后触发重查
- 重新核查中 → 已完成：新一版问题清单和报告生成
- 已完成 → 已归档：任务封存或归档

### 8.2 互动状态
- 等待补充：等待用户补充材料
- 等待确认：等待用户确认 AI 提炼的参数或材料
- 已触发重查：已触发重查，正在处理
- 结果已更新：已更新问题清单与结论

### 8.3 材料状态
- 待补充：待补充
- 已就绪：已就绪
- 已更新：已更新
- 已重查：已重新核查

### 8.4 问题状态
- 未处理：未处理
- 已修正：已修正
- 已确认：已确认
- 已忽略：已忽略

### 8.5 参数变更状态
- 草稿：用户在对话中提出调整建议
- 待确认：AI 已提炼参数变更，待用户确认
- 已生效：参数已生效
- 已回滚：参数被回滚

## 9. 数据流与字段需求

### 9.1 对话框输入/输出

| 方向 | 数据项 | 来源/去向 |
|------|--------|-----------|
| 输入 | 用户文本消息 | 对话框用户输入 |
| 输入 | 补充材料文件 | 对话框附件上传 |
| 输入 | 参数变更指令 | 对话中用户确认的参数调整 |
| 输出 | AI 回复消息 | 基于当前任务上下文生成 |
| 输出 | 更新后的问题清单 | 重查后生成新版本 |
| 输出 | 更新后的报告 | 重查后生成新版本 |

### 9.2 问题清单字段

| 字段 | 说明 |
|------|------|
| 问题编号 | 唯一标识，如 Q001 |
| 问题描述 | 核查发现的具体问题 |
| 问题等级 | Critical / Major / Minor |
| 问题状态 | 未处理 / 已修正 / 已确认 / 已忽略 |
| 关联材料 | 问题关联的上传材料 |
| 判定依据 | AI 判定该问题的依据说明 |
| 版本号 | 问题首次出现的版本号 |

### 9.3 参数变更字段

| 字段 | 说明 |
|------|------|
| 参数名 | 变更的参数名称，如基线日期、方案版本 |
| 原值 | 变更前的参数值 |
| 新值 | 变更后的参数值 |
| 变更时间 | 参数变更的时间 |
| 触发重查 | 是否触发重新核查 |

### 9.4 版本记录字段

| 字段 | 说明 |
|------|------|
| 版本号 | V1、V2、V3... |
| 生成时间 | 版本生成时间 |
| 变更摘要 | 本次变更的材料/参数变更说明 |
| 问题变化 | 新增/解决/升级的问题数量 |
| 变更类型 | 材料补充 / 参数调整 / 重查 |

## 10. 异常处理

| 场景 | 处理方式 |
|------|----------|
| 用户补充材料但没有说明用途 | AI 自动识别材质类型，并提示“将纳入本次核查” |
| 提问与核查无关 | 温和拒绝，并提示继续当前任务 |
| 用户上传大量无关文件 | 仅保留与任务相关文件，提示“未纳入当前核查” |
| 新增材料不影响已有问题 | 继续保留原问题，并展示“无新增影响” |
| 用户反复重查 | 允许，但需保留版本历史并展示差异 |
| 重查后问题变多/变少 | 显示“变化趋势”，提供版本对比 |
